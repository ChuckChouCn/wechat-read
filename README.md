# wechat-read

[![License](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Python](https://img.shields.io/badge/Python-3.10%2B-3776ab.svg)](https://www.python.org/)
[![Platform](https://img.shields.io/badge/Platform-Windows%20only-0078d4.svg)](#兼容性)

**Windows 专用的微信聊天记录读取 Skill —— 装给 AI 用，一行命令取数，AI 自己做总结。**

> "总结今天微信" → 读完全部会话，按话题分类给你一份简报
>
> "XX 群这两天聊了什么" → 聚类成话题再总结

所有数据都在你本机，不上传任何服务器。

---

## 它解决什么

微信自带的搜索和导出很难用：跨群总结要一个个翻，找待办全靠手动，
历史消息基本没法追溯。

wechat-read 把这件事交给 AI —— 它读出你本机的聊天记录，
按你的问题做归纳。**AI 负责理解，工具只负责把数据如实取出来。**

|  | 微信自带 | wechat-read |
|---|---|---|
| 跨群总结 | ❌ 只能一个个翻 | ✅ 一次读完所有会话 |
| 追问细节 | ❌ 无法提问 | ✅ 直接问 AI |
| 按话题归类 | ❌ 没有 | ✅ AI 自动聚类 |
| 数据去向 | — | ✅ **全在本机** |

---

## 为什么用它

**Windows 专用。** 只做 Windows 一件事，不做跨平台妥协 ——
密钥从运行中的微信进程内存里读，数据目录靠微信自己的配置定位。

**够简单。** 只有 **2 个依赖**（pycryptodome、zstandard），
没有 SQLCipher 之类的原生编译依赖，`pip install` 不会卡住。
安装就是"复制文件夹 + 装依赖"，卸载就是删文件夹 —— 不碰 PATH、不写注册表。

**够快。** 全量读取一天 2000+ 条消息（含解密）约 **1.5 秒**。
日常提问走增量缓存，只处理新消息。

**够小。** 峰值内存约 **100MB**（主要是 Python 运行时），纯代码 5500 行。
解密是自己实现的页级 AES（`db/crypto.py`），不引入重型数据库驱动。

## 怎么用

装好之后**直接对 AI 说人话**，不用记命令：

| 你说 | AI 会做 | 结果在哪 |
|---|---|---|
| "总结今天微信" | 读今天全部会话，按话题类型整理 | 💬 聊天框 |
| "总结一下 XX 群这两天聊了什么" | 把该群消息聚类成话题再总结 | 💬 聊天框 |
| "今天有什么重要通知？" | 挑出通知类内容 | 💬 聊天框 |
| "XX 群有多少人" | 查群成员 | 💬 聊天框 |
| "搜一下谁提到了 XX" | 搜联系人和相关会话 | 💬 聊天框 |
| **"微信日报"** / **"今天的日报"** | 当天全部会话整理成日报 | 📄 **HTML 文件** |
| "导出成 Markdown" | 生成 md 文件 | 📄 文件 |

> **大部分情况在聊天框回答。** 只有两处产出文件：
> 说「**日报**」（那是在要一份能存下来的文档），
> 或明说「导出 / 存成文件」。
> 随口问「今天微信有什么」不会被塞一堆 HTML。

想自己动手也行：

```powershell
& "<skills 目录>\wechat-read\wechat-read.cmd" sessions --limit 10
& "<skills 目录>\wechat-read\wechat-read.cmd" summarize "群名" --output pack.json
```

## 安装

### 需要准备

- **Windows 10 / 11**（只支持 Windows）
- **Python 3.10+**
- **微信 4.x**（Windows 版，已登录并正在运行 —— 提密钥需要）
- **Claude Code / Codex / 其他能执行命令的 AI**

### 一条命令

把项目下载到本地，在项目目录里执行：

```powershell
.\install.ps1
```

它把项目复制到**你 AI 的 skills 目录**，并装好依赖。装完是一份自包含的东西：

```
<skills 目录>\wechat-read\
├── SKILL.md          ← AI 在这里发现 Skill
├── wechat-read.cmd   ← 调用入口
├── cli.py
├── guides\
├── requirements.txt
└── db\ parser\ service\ skills\ keyprovider\
```

没探测到你的 AI 用哪个目录？指定即可：

```powershell
.\install.ps1 -Dest "D:\你的-agent\skills\wechat-read"
```

### 初始化密钥（只做一次）

```powershell
& "<skills 目录>\wechat-read\wechat-read.cmd" init
```

从正在运行的微信进程内存里读出解密密钥，存到
`C:\Users\<你>\.weixin-read\keys.json`。**以后都不用再做**，
只有微信换账号或清了聊天数据时才需要重跑（加 `--force`）。

### 验证

```powershell
& "<skills 目录>\wechat-read\wechat-read.cmd" status
```

`ready` 是 `true` 就成了。

## 它是怎么工作的

```
微信数据库(加密)  →  本机解密  →  结构化 JSON  →  AI 归纳  →  给你看
       ↑                                                    ↑
   只读取，不改动                                     不联网，不上传
```

- **解密**：自己实现的 SQLCipher 4 页级 AES-256-CBC
  （`db/crypto.py`），解出来就是标准 SQLite
- **取数**：`summarize` 按**时间区间闭包**语义读取 ——
  说"今天"就覆盖 `00:00:00 ~ 23:59:59`，区间内一条不落，
  不是"取最近 N 条"那种会静默丢数据的翻页语义
- **归纳**：由 AI 完成。项目不调用任何 LLM、不需要任何 API Key

**增量缓存**：已总结过的内容存在 `~/.weixin-read/summaries.json`，
下次只处理新消息，不重复读历史。

**可溯源**：每条结论都带来源消息 ID，渲染时校验真实性 ——
AI 编造的 id 会被丢弃，保证结论能对回原文。

## 当前限制

- **图片、语音、视频**只显示 `[图片]` `[语音 12秒]` 这类标记，
  不做图像识别或语音转文字
- **文件**只显示文件名，不解析内容
- **看不了已删除的消息**
- 没有自动定时推送，需要你开口问
- AI 的归纳会标注「推断」，但仍可能出错 ——
  重要事项建议点回原文确认

## 隐私

- ✅ **只读**：不发送、不修改、不删除任何微信数据
- ✅ **不联网**：不从你电脑上传任何数据

## 常见问题

**Q：一定要用 Claude Code 吗？**
任何能执行命令行命令的 AI 都可以（Codex、Cursor 等）。
本项目不绑定特定 AI，也不需要 API Key。

**Q：为什么只能看 Windows？**
macOS 和 Linux 版微信的数据存储方式不同，需要单独适配。

**Q：终端里中文/emoji 显示成乱码？**
先执行 `chcp 65001` 切到 UTF-8。写到文件里的内容不受影响
（CLI 已强制 UTF-8 输出）。

**Q：用 `>` 重定向存 JSON 报编码错？**
PowerShell 的 `>` 会写成 UTF-16（5.1）或带 BOM 的 UTF-8（7.x）。
**取数据请用 `--output`**，由程序自己写标准 UTF-8：

```powershell
wechat-read summarize --output pack.json      # 对
wechat-read summarize > pack.json             # 错
```

**Q：总结得不准怎么办？**
AI 的归纳会有误差，标了「推断」的条目尤其要留意。
所有结论都带来源消息 ID，可以点回原文核对。

**Q：微信更新后还能用吗？**
大概率可以。若微信改了数据格式导致失效，需要更新本项目。
